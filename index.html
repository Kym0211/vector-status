Team update · offline-signer-cli

Vector: offline signing without durable nonces

A cold wallet can now authorize SOL transfers, SPL token transfers, staking and DAO votes by signing a 32-byte hash — never a Solana transaction. The on-chain program is deployed and the flow has been exercised end-to-end with real funds.

Live on mainnet-beta FkCL7nUJym3Yc9PVgr7TQ3TRn5uJApu7FdGSV1X6rKVd

Why we changed the approach

The old flow relied on durable nonces, which the Solana Foundation is deprecating. It also carried on-chain state an attacker could grief. Vector removes both problems: there is no nonce account, and the only external dependency is the native Ed25519 precompile, which ships with every cluster and cannot be turned off.

The trade is that the cold wallet signs an opaque digest rather than a transaction, so transactions never expire — the hot wallet attaches a fresh blockhash at broadcast time. That removes the ~60-second signing window that made air-gapped Solana signing painful.

How it works

Two accounts per cold wallet

AccountDerivationOwnerHolds
Vector PDA ["vector", authority] Vector program Authority key, hashchain seed
Vault PDA ["vault", authority] System program SOL, SPL token accounts, stake authority

State and value are split because SystemProgram.transfer refuses to move SOL out of an account carrying data. The vault stays data-free so it can behave like an ordinary wallet, while the program signs for it via invoke_signed.

Replay protection

digest    = sha256(seed ‖ action_tag ‖ program_id ‖ payload)
new_seed  = sha256(seed ‖ digest)

Every successful action advances the seed, so a signature is single-use and non-rewindable. Binding program_id means a signature valid against one deployment can never replay against another.

What crosses the air gap

The online machine writes unsigned-tx.json. The offline machine recomputes the digest from the raw instructions, renders what they actually do, and only then signs — producing signed-tx.json. Nothing else moves between them, and the offline machine needs no network, no RPC and no blockhash.

Security review

Three independent review passes were run before deployment: a targeted security review, a multi-agent code review, and a custom probe testing 21 named attack hypotheses against the on-chain program. Five findings, all now fixed and re-verified on chain.

FindingSeverityStatus
Offline signer displayed unverified metadata while signing an opaque digesthighfixed
Token transfer to a new recipient failed at the last stepmediumfixed
Redundant PDA derivation burning computelowfixed
Program could re-enter itself via sub-instructionlowfixed
Digest not bound to program ID (cross-deployment replay)lowfixed

The first finding is the one that mattered. The signer previously showed a producer-supplied summary while signing bytes it never checked, so a compromised online machine could display “0.001 SOL to Alice” and have the cold wallet authorize a full drain. The signer now recomputes the digest from the raw instructions and renders the decoded action — what you see is provably what you sign.

One deliberate trade-off

Supporting DAO voting required relaxing a rule. SPL Governance creates the vote record as part of casting a vote, and creating an account needs someone to pay rent and sign for it. The vault cannot pay rent, so the hot wallet has to co-sign that one instruction.

ScenarioBeforeAfter
Compromised hot wallet moves fundsimpossibleimpossible
Compromised hot wallet alters what was signedimpossibleimpossible
Compromised cold wallet drains the vaultpossiblepossible
Compromised cold wallet debits the hot walletimpossiblepossible, bounded

The headline guarantee is untouched: a compromised online machine still cannot move funds. The widening only applies when the cold key is already compromised, at which point the vault is lost anyway. Three mitigations bound it — 12 of 13 commands never use a co-signer, the broadcaster refuses co-signing for any program other than SPL Governance, and the signing screen prints an explicit warning naming the account that can be debited.

Open decisions

Needs a decision · budget

No paid audit yet

The three review passes are a solid pre-audit, not a substitute for one. Typical engagement with a firm like Neodyme, OtterSec or Zellic runs weeks and five figures. Recommended before onboarding third-party funds; not required to keep testing.

Needs input · product

Which DAO do we vote in?

The four governance commands work against standard SPL Governance. Naming a target realm lets us finish mainnet verification and confirm the decoder renders that DAO's proposals legibly at signing time.

Operational

Cold key custody

The test cold key was generated on a networked machine with no recorded mnemonic. Production keys must be generated air-gapped, backed up in two physically separate locations, and documented so a successor can operate them.

Try it

The branch is feat/vector-integration. The offline test suite needs no keys, no funds and no network — a good first sanity check: 

pnpm install
pnpm exec ts-node smoke/adversarial-offline.ts   # 13 attacks, all refused
pnpm exec ts-node smoke/function-coverage.ts     # every command builds + signs

Reviewing the on-chain program is about a fifteen-minute read: the interesting files are the precompile introspection and the sub-instruction decoder. README.md covers the full flow and docs/mainnet-deployment.md covers deployment, accepted risks and the operational runbook.
